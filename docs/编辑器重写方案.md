# 笔记编辑器重写方案（对齐飞书文档）

> 分支：`feat/editor-single-host`
> 目标：单 contenteditable 的块文档，跨块**原生**选区，编辑手感和飞书文档一致。

## 一、为什么必须重写

现在每个块是独立的 `contenteditable`（`.blk-txt`）。浏览器不允许一个**文字选区**横跨两个可编辑根，
所以：

- 拖选只能按块走，端点只能用「绘制高亮」假装选中；
- 双击选词、Shift+点击扩选、Home/End 跨块、方向键跨块都得手写；
- 复制出来的 HTML 结构不连续。

这些在单宿主模型里都是浏览器原生行为。

## 二、目标模型

```
<div id="preview" class="preview" contenteditable="true" spellcheck="false">
  <div class="blk blk-h2" data-i="0"><span class="blk-mark-hash"></span>标题</div>
  <div class="blk blk-p"  data-i="1">正文…</div>
  <div class="blk blk-bullet" data-i="2"><span class="blk-dot"></span>列表项</div>
  <div class="blk blk-empty" data-i="3"><br></div>
</div>
```

关键差异：

| 项 | 现在 | 之后 |
| --- | --- | --- |
| 编辑宿主 | 每块一个 `.blk-txt` | 整个 `#preview` 一个 |
| 块标记（`•`、`1.`、`☐`、`#`） | 块内兄弟节点，`contenteditable` 内 | 改成 **CSS `::before`**，不参与编辑、不被选中 |
| 块类型 | `data-kind` + 渲染时套 class | 同上，但内容就是块元素的 `innerHTML` |
| 光标定位 | `focusBlock(i)` 聚焦 `.blk-txt` | `caretAt(i, offset)` 用 Range 落点 |
| 选区 | 每块独立 | 全文档一条，跨块原生 |
| 源码块（代码/公式/表格） | 内部 `textarea` | 仍是 `textarea`（`contenteditable=false` 子节点，可选中不可编辑） |

## 三、事件映射（飞书逻辑）

| 输入 | 行为 |
| --- | --- |
| `Enter` | 在光标处**拆块**；光标后内容进新块；列表/引用/待办沿用当前类型 |
| `Shift+Enter` | 块内软换行（`<br>`） |
| 块首 `Backspace` | 与上一块**合并**（当前块内容拼到上一块尾），光标落在拼接点 |
| `Delete`（选区跨块） | 删除选区覆盖的全部内容（原生行为，删除后由 `input` 归一化块结构） |
| `Tab` / `Shift+Tab` | 列表项缩进 / 反缩进（只改 `data-depth`，不改内容） |
| `↑` / `↓` | 原生跨块移动（单宿主后自动生效，删掉现有手写逻辑） |
| 粘贴多行 | 按行拆块；纯文本走 `insertText`，富文本走 `insertHTML` 后归一化 |
| `[[链接]]` `#标签` | `input` 后做内联替换（失焦时统一归一化，避免打字过程抖动） |
| `/` | 普通字符（菜单走右键） |
| 自动格式（`# ` `- ` `1. ` `[] ` `> `） | `input` 中检测行首标记 → 换 `data-type` 并删标记 |

## 四、归一化（normalize）——整套的核心

每次 `input` 后执行一次 `normalize()`：

1. 遍历 `#preview` 的直接子元素，重编 `data-i`；
2. 空块（无文本无 `<br>`）补一个 `<br>`，保证可落光标；
3. 合并相邻同级、同类型的列表/引用块（可选）；
4. 把浏览器可能插入的 `<div>`/`<span style>` 转成纯 inline HTML（白名单）；
5. `writeBack()`：块数组 → markdown 文本（沿用现有 `htmlToInline`）。

**保光标**：normalize 前后记录 `(块下标, 块内字符偏移)`，重排后重建 Range 复原，
避免打字时"光标跳走"。

## 五、兼容与迁移

- 数据格式不变：`note.content` 仍是 markdown，`parseBlocks()` 继续用它；
- 渲染器 `blockHtml()` 改成输出"块元素 + 纯 inline 内容"；
- 画布卡片、笔记列表、搜索都不受影响（只读 `content`）。

## 六、测试策略

现有 66 条 UI 自检里，涉及 `.blk-txt` 的（`activeEditor()`、`setBlockText()`、`clickBlock()`）要改成新模型：

- `activeEditor()` → 返回 `document.activeElement.closest('.blk')`；
- `setBlockText(i, text)` → 直接写块元素 `innerHTML` 再 `input`；
- `clickBlock(i)` → 按块元素中心坐标点击。

新增覆盖：

1. 跨块原生选区：拖选 1→3 块后 `getSelection().toString()` 含三块文字；
2. 回车分块、Shift+回车软换行；
3. 块首退格合并、光标位置正确；
4. 粘贴多行拆块；
5. Tab 缩进、Shift+Tab 反缩进；
6. `Ctrl+Z/Y` 在跨块删除后能正确回滚；
7. 飞书手感回归：双击选词、三击选段、Home/End、Ctrl+A（应选中整个文档内容而不是单个块）。

## 七、实施步骤（每步都能独立验证）

1. **骨架**：`#preview` 单宿主 + 渲染块元素（先不接管键盘），跑通现有只读渲染；
2. **光标与输入**：`caretAt` / `offsetInBlock` / `normalize` 保光标；
3. **Enter / Shift+Enter / Backspace 合并 / Delete**；
4. **粘贴与自动格式**；
5. **Tab 缩进、方向键**（单宿主后大多免费）；
6. **多块选中与右键菜单**（改用原生选区范围）；
7. **撤销栈**改按"操作快照"记录（沿用现有 600ms 合并策略）；
8. **测试适配 + 新增用例**，全绿后合并 main。

## 八、风险

| 风险 | 对策 |
| --- | --- |
| 输入法（中文）组合期被 normalize 打乱 | `compositionstart/end` 期间跳过 normalize |
| 浏览器在 `contenteditable` 里插 `<div>` | 白名单清洗，且只在 `input` 后做 |
| 撤销栈与 DOM 不一致 | 撤销恢复后用 `render()` 全量重建，再复原光标 |
| 大规模 DOM 重排导致卡顿 | 只重排受影响的块，整篇重排仅在结构变化时 |
